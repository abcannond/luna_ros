Commands to run and what they do
================================

Short reference: what to run and in what order. Full details: LAUNCH_COMMANDS.md.

Repo root = this folder (luna_ros; Dockerfile and ros2_ws here). Run git and "drun" from here. After drun you are inside the container in /ros2_ws. Use dbash to open another shell in the same container.

Where to run:
  Host (repo root): git clone/pull, docker build, ./run_ros_image.sh (drun), dbash.
  ROS commands: inside the container (cd /ros2_ws, source install/setup.bash, then launch/topic/node commands).

Worlds (Gazebo):  world:=ucf_arena (default)  |  world:=artemis_arena
If "model could not be resolved" or "Failed to load world": build and install luna_ros2_worlds, then source install/setup.bash.

----------------------------------------------------------------------
Optional: Shell aliases (once per machine)
----------------------------------------------------------------------

Add to ~/.bashrc, then source ~/.bashrc:

  alias dbld='docker build -t luna_ros:latest .'
  alias dbld_nc='docker build --no-cache -t luna_ros:latest .'
  alias drun='./run_ros_image.sh luna_ros:latest'
  alias dbash='docker exec -it $(docker ps -q -f "ancestor=luna_ros:latest") /bin/bash'
  alias gitmod='git submodule update --init --recursive'

Then: dbld (build image), drun (run container), dbash (new shell in container), gitmod (update submodules).

----------------------------------------------------------------------
FIRST TIME (once per machine or clone)
----------------------------------------------------------------------

Host, repo root:
  git clone <repo> && cd luna_ros
  git submodule update --init --recursive   # or gitmod
  docker build -t luna_ros:latest .        # or dbld
  ./run_ros_image.sh luna_ros:latest       # or drun

Inside container:
  cd /ros2_ws
  source /opt/ros/jazzy/setup.bash
  colcon build --symlink-install
  source install/setup.bash

Ignore "quad_swerve_controller not found". If "package twist_stamper not found": colcon build --symlink-install --packages-select twist_stamper then source install/setup.bash.

Run drun from repo root only; otherwise you can get duplicate package names / CMake errors. Fix and full explanation: LAUNCH_COMMANDS.md (Prerequisites / Duplicate package names).

After git pull: same colcon build + source install/setup.bash; restart Gazebo and RTAB-Map+Nav2 if they are running.

----------------------------------------------------------------------
SIM: Single command (gazebo brings up RTAB-Map + Nav2 automatically)
----------------------------------------------------------------------

  cd /ros2_ws && source install/setup.bash
  ros2 launch lunabot_2425 gz_bringup.launch.py

  Starts Gazebo, waits ~18 s for the simulation to load, then automatically
  starts RTAB-Map, Nav2, and RViz (with Nav2 plugin, map, costmaps, planner).
  One terminal — no separate launch for mapping.

  Artemis arena:      ros2 launch lunabot_2425 gz_bringup.launch.py world:=artemis_arena
  Gazebo only:        ros2 launch lunabot_2425 gz_bringup.launch.py launch_mapping:=false
  Fiducial off (visual odom only): ros2 launch lunabot_2425 gz_bringup.launch.py launch_fiducial_localization:=false

----------------------------------------------------------------------
Optional: run RTAB-Map + Nav2 separately (e.g. if Gazebo already running)
----------------------------------------------------------------------

  ros2 launch luna_mapping rtabmap_nav2_sim.launch.py launch_rviz:=true

----------------------------------------------------------------------
Teleop (optional)
  dbash
  cd /ros2_ws && source install/setup.bash && drive
  i = forward, comma = back, j/l = left/right, k = stop. Publishes to /cmd_vel; sim includes twist_stamper.

----------------------------------------------------------------------
Main topics
----------------------------------------------------------------------

  /map                            Occupancy grid (RTAB-Map)
  /scan                           Depth→laserscan (Nav2 obstacles)
  /odom                           Odometry
  /cmd_vel                        Velocity (Nav2 or teleop)
  /plan, /local_plan              Global and local path
  /local_costmap/costmap, /global_costmap/costmap
  /camera/camera/color/image_raw  RGB
  /fid_cams/<name>/image_raw, camera_info   Wheel-pod cameras (if bridge publishes them)

----------------------------------------------------------------------
Launch arguments (optional)
----------------------------------------------------------------------

  use_rtabmap_odom:=true     Use RTAB-Map visual odom instead of Gazebo odom
  launch_nav2:=false         Mapping only (no Nav2)
  launch_mapping:=true           Auto-start RTAB-Map+Nav2 after Gazebo (gz_bringup, default)
  launch_mapping:=false          Gazebo only (no mapping)
  launch_fiducial_localization:=true   (default) Fiducial map->odom + Gazebo wheel odom for costmap accuracy
  launch_fiducial_localization:=false  RTAB-Map visual odom instead (can drift)

----------------------------------------------------------------------
Troubleshooting
----------------------------------------------------------------------

  Robot doesn’t move:  ros2 control list_controllers -c /controller_manager (luna_cont active?). Details: LAUNCH_COMMANDS.md.
  No map / map frame missing:  Start Gazebo first; rebuild luna_mapping; check camera topics. Details: LAUNCH_COMMANDS.md.
  Blocky costmap:  Check map→odom and odom→base_link TF; start Gazebo then stack. Details: LAUNCH_COMMANDS.md.
  Duplicate nodes:  Run RTAB-Map+Nav2 launch in only one terminal. Details: LAUNCH_COMMANDS.md.
  "Localization inactive" in Nav2 panel:  Expected with RTAB-Map SLAM (no AMCL). Localization comes from map→odom TF; can be ignored.
  Robot out of arena / map drift:  Ensure fiducial sees marker at startup (face marker or drive toward it). Use launch_fiducial_localization:=true (default) for wheel odom + fiducial map→odom. Grid/ProbHit/ProbMiss tuned for more stable map.
